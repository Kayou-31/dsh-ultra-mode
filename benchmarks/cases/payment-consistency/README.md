# 付款一致性案例

只把 `challenge/` 导出给候选；`organizer/` 含参考修复、冻结评分序列及自验结果。候选从 `SPEC.md`、`TASK.md` 开始。Node.js 24 及以上，无第三方依赖。

评分器导出 `grade(candidateDir)`，其中 candidateDir 是导出的 challenge 根。评分覆盖正常付款与退款、事件重试、租户边界、事务失败后的读取、组合序列及缓存确实发挥作用。通过数是业务检查数，不是模型请求数。

本案例的确定性内存事务只覆盖顺序执行的业务序列，不模拟原生线程竞态、网络故障或真实数据库。评分会执行候选代码；它不是安全沙箱。仅提示候选不要读 organizer 不能形成访问隔离，隔离需由统一导出与运行环境实施。
