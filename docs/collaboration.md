# 子代理协作增强（0.4.0-rc.1 候选版）

协作增强为 Agent 提供后台派发、代理间信息、续作、事件等待、中断和状态查询。它与 Ultra 算力模式分别开关：可以让普通 Agent 使用协作，也可以让 Agent + 决策或并发 Ultra 使用协作。当前文档描述本次候选源码，正式发布版仍为 [v0.3.2](https://github.com/Kayou-31/dsh-ultra-mode/releases/tag/v0.3.2)；不能用旧版本的验收记录声称新增协作功能已经通过真实模型验收。

## 开启与选择

协作增强默认关闭，按会话保存当前选项。使用协作选项或以下命令切换；改变开关影响后续任务，不中断已启动的任务。选项驻留 Host 内存，重启后按配置重新初始化。

```text
/team on
/team off
/team
```

`/team` 查询当前协作选项。`/ultra` 继续管理原有 Ultra 模式，两种命令不会替对方改变选择。

| Ultra 选择 | 协作关闭 | 协作开启 |
| --- | --- | --- |
| 关闭 | 普通主 Agent 的原有能力 | 普通主 Agent + 本次任务的协作工具；主 Agent 模型与思考档位不变 |
| Agent + 决策 | 普通主 Agent + 只读 Max 决策辅助 | 保留上述执行和决策分工，额外提供协作工具 |
| 2／3／4／5 路 | N 条 Max worker + 1 条 Max decision | 各独立路线可使用协作工具；worker 及后代继续受研究权限限制 |

协作不会自动增加一个 Max decision，也不会将普通 Agent 强制改为 Max。使用 Ultra 的路线仍遵循 Ultra 的 Max 设置。原生 `subagent`、`send_message`、`interrupt_agent` 等工具保留自己的名称、配置及宿主行为；本插件使用 `ultra_` 前缀增加工具，不替换它们。

## 六个工具

这些工具提供给开启协作的 Agent，由 Agent 根据任务调用；用户无需手动填写工具 JSON。

| 工具 | 参数 | 返回与行为 |
| --- | --- | --- |
| `ultra_spawn_agent` | `task_name`、`message` | 返回真实子代理 `id`、父 ID、任务名及状态。只等待子代理创建和初始任务被接受，不等待任务完成；父 Agent 可以继续独立工作 |
| `ultra_send_message` | `target`、`message` | 返回 `{ queued: true, wakeup: false }`。信息进入有界邮箱，运行中的目标在后续步骤接收，空闲目标保持空闲 |
| `ultra_followup_task` | `target`、`message` | 给自己的直接子代理追加任务，复用真实 ID 和已有上下文。运行中进入后续步骤，空闲子代理由宿主续接；一并发送此前排队的信息 |
| `ultra_wait_agent` | `targets`、可选 `timeout_ms`、`after_cursor` | 等待 1–8 个子代理中首个新完成、失败或取消；返回 `agents`、`cursor`、`timedOut`。默认 30000 毫秒，允许 0–60000；超时返回进展，不取消子代理 |
| `ultra_interrupt_agent` | `target` | 请求中断自己创建的子代理或后代当前活动，保留可续接上下文。返回时可能仍在停止，需从后续状态核对 |
| `ultra_list_agents` | 无 | 返回本组登记子代理的真实身份、任务、状态与结果快照 |

`task_name` 在同一父 Agent 下唯一，最多 128 字符。已有子代理需要新任务时使用续作；不要用另一个身份重复派发同一任务。工具返回的 `starting`、`running`、`completed`、`failed`、`cancelled` 分别表示创建中、执行中和宿主轮次的终态；完成不等于业务验证通过。

`ultra_wait_agent` 使用宿主事件更新的账本，没有新事件时不调用模型轮询。继续等待同一组目标时传回上一次 `cursor`，已消费的结果文本不会重复返回；新续作的终态仍可读取。cursor 只适用于产生它的协作组，不能跨会话或跨任务复用。

## 分工、消息与上下文

每个子代理有独立会话上下文。派发时应提供自包含的任务、必要材料、文件范围、期望产物及验收条件；父 Agent 继续处理不依赖子代理结果的工作，再收集结果、核对证据并完成交付。续作复用子代理自己的上下文，不重新创建会话。

信息工具只允许本组内的直接父子互发，不能跨协作组访问，也不能直接给兄弟 Agent 发消息。需要跨分工同步时，通过共同父 Agent 汇总并转发。任务续作仅允许父 Agent 给自己的直接子代理发起；中断允许祖先控制自己创建的后代。组内成员可查询本组状态并等待已登记子代理。

消息带有代理来源，属于协作信息，不增加用户授权。排队凭据不证明目标已经接收或采纳；已发出的模型请求不会被中途改写。没有可用的非唤醒投递通道时，信息保留在邮箱中，等待显式续作，不静默改成唤醒操作。原生 `send_message` 在空闲目标上可能启动新轮次，因此它与 `ultra_send_message` 的行为不同。

各 Agent 仍访问同一份工作目录，本插件不自动创建 worktree。并行修改前明确文件所有权；交叉审查、证据查找等任务可分别推进，涉及同一文件的变更由父 Agent 协调。Ultra worker 及后代的读取、命令与写入边界仍由 Ultra 研究权限和宿主守卫约束。

## 宿主要求与容量

目标宿主为 **DSH Desktop / Host 0.2.0-rc.2**，需要可用的 `subagents` continuation 服务和支持 `prepareContinuable` 的 provider，默认 provider 名为 `spawn`。插件通过公开 `startContinuable` 创建子代理，让宿主处理模型、preset、工作目录、审批、sandbox 与委派深度的继承，不自行建立无限深度的 AgentLoop。

创建时读取宿主的明确 `maxDepth` 并交回原生服务执行；宿主深度或容量不足时拒绝派发。子代理占用正常委派深度，协作不会像独立 Ultra worker 那样免去这一层。可继承工具按父 Agent 的实际 schema 过滤，不将父 Agent 自有工具全部扩散给子代理；任意 `run_code` 不进入新增派发的继承列表。宿主依赖或 provider 不可用时，提示协作未启动，并保留原有派发能力。

| 限制 | 默认值 | 范围 |
| --- | --- | --- |
| `collaborationEnabled` | `false` | 新会话的协作初始选择，与 Ultra `enabled` 分离 |
| `collaborationProvider` | `spawn` | 必须支持 continuable 创建的宿主 provider |
| `collaborationMaxAgents` | `8` | 每个协作组最多登记的子代理数，可配置 1–32；创建中与已完成子代理也占组内名额，续作复用原名额 |
| 目标邮箱 | `32` 条 | 每个目标的未投递信息上限，超过时明确拒绝 |
| 单次文本 | `20000` 字符 | 派发、消息与续作文本上限；合并邮箱与续作后也须符合上限 |

宿主自身的深度和活动子代理容量限制同时有效，实际可创建数取决于两侧限制。更多子代理会增加请求和用量；组内数量不是总 API 请求数或固定费用倍率。

## 生命周期与验证边界

协作组绑定当前主任务的 turn 或独立 Ultra 路线生命周期。任务结束、父取消、路线释放或插件卸载时，关闭新的协作操作，取消并等待已接受的内部操作，再交由原生服务清理本组创建的子代理及后代。中断工具本身不等于释放整个组；续作能力只在本组仍有效时使用，不能把旧 child ID 带到下一任务。

本次纯模块回归使用离线 adapter 验证创建竞态、有界消息、续作、事件等待、cursor、取消及收尾。宿主契约与界面验证需另外检查，完整状态见 [测试指南](testing.md)。这些检查不请求真实模型，不能证明新增功能提高业务成功率、降低 Token 消耗或完整复现 Codex 的内部实现。后续收益评估应沿用 [冻结业务案例](../benchmarks/README.md)，在相同模型、权限与任务条件下多次对照，记录关键失败、最终补丁、完整用量和耗时。

实现入口见 [`src/collaboration.ts`](../src/collaboration.ts) 的组内账本与 [`src/collaboration-host.ts`](../src/collaboration-host.ts) 的宿主适配；会话开关和任务生命周期由 [`src/index.ts`](../src/index.ts) 管理。
