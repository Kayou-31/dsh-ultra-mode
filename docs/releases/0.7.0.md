三个功能包按需选择：Ultra 提供完整协作、多路线和工程记忆；Memory 提供独立记忆；Decision 保留普通主 Agent 并增加协作与复核。不要求同时安装三个包。组合时证据配置优先级为 Memory > Ultra > Decision，同一 scope 只启用一个协调插件。


**这次把“记住”和“按需找回”放进了工程任务的上下文管理。** Ultra-Memory 可独立安装，也随 [Ultra 0.7.0 三包](https://github.com/Kayou-31/dsh-ultra-mode/releases/tag/v0.7.0) 一起发布，两处 Memory TGZ 字节完全相同。复用 Memory-Continuity 的结构与设计经验，不连接其运行时或人物数据。

## 这次改了什么

| 改动 | 对使用者的意义 |
| --- | --- |
| 五层工程记忆 | 目标与约束、进度、决策、历史证据、未完成事项分层组织，默认 8192 字节预算 |
| 条件检索注入 | 按当前用户消息关键词选择相关记录，显示来源、选择理由和省略原因 |
| 主动进度查询 | 新增 ultra_memory_status，提供 overview / association / evidence 三级读取、版本比较和分页 |
| 保留后来要求 | “取消 A、改做 B、不能删除原件”不会因下一句仅为“继续”被过滤；模型整理不能冒充真实用户原话 |
| 压缩与恢复接入 | 必要要求超预算时暂停新增压缩；自有动态快照不反复回灌为新事实，归档后仍可读回原文 |
| 独立源码交付 | 独立依赖锁、构建、测试、CI 和中文文档，构建入口不依赖 Ultra 父仓库 |
| DSH rc.3 兼容 | 保留 rc.2 支持并增加 rc.3，三包继续共用一份核心实现 |

Memory 自身不创建模型或子代理，不需要额外密钥、embedding 或数据库。默认启用项目证据与分层注入；历史压缩、阶段归档和全局知识仍默认关闭。记录的进度不等于已经重新检查当前工作区。

## 下载与升级

| 附件 | 用途 |
| --- | --- |
| dsh-external-dsh-ultra-mode-0.7.0.tgz | 完整 Ultra |
| dsh-external-dsh-ultra-memory-0.2.0.tgz | 独立 Memory |
| dsh-external-dsh-ultra-decision-0.2.0.tgz | 独立 Decision |
| dsh-ultra-mode-0.7.0-source.zip | 三包共同源码、测试、构建脚本、文档和依赖锁 |
| dsh-ultra-mode-0.7.0-evidence.zip | 构建、测试、两套 SDK 包矩阵、来源及归档校验 |
| RESULTS.md、RELEASE-RECEIPT.json、SHA256SUMS.txt | 验证结果、提交和包对应关系、下载校验值 |

1. 保留旧包、profile、项目证据与宿主日志。
2. 校验 TGZ 后通过 DSH 本地插件包流程安装；入口为 @dsh-external/dsh-ultra-memory，配置节点仍是 ultra-memory。
3. 使用 Node 22+ 和一致的 rc.2 或 rc.3 原生组件，完整重启。
4. 先使用默认项目记忆；开启压缩或跨项目知识前核对 README 中的容量、持久化能力与授权配置。

可以对模型说：“先查看项目进度，再按下一步读回原始证据。”模型工具为 ultra_memory_status、ultra_memory_search 和 ultra_memory_get。独立仓库与三包里的 Memory 是同一插件，不要重复安装。

## 验证结果

- 主仓库构建、类型检查与完整测试通过：745 项，743 通过，2 项 Windows 符号链接权限跳过。
- 独立源码安装、构建、类型检查与完整测试通过：260 项，259 通过，1 项同类跳过。
- rc.2 原生接入回归 32/32；独立构建 Memory 运行文件与三包版本 SHA-256 相同。
- 最终三包在 rc.2、rc.3 各执行 7 种原生 Loader 安装/卸载组合，精确包哈希及远程 CI 状态见发布回执。
- 离线业务参考检查 66 项，模型请求 0。没有新增付费模型实验，历史成绩不算本版成绩。

详细失败记录与复现命令见 [RESULTS](https://github.com/Kayou-31/Ultra-Memory/blob/v0.2.0/docs/releases/0.2.0/RESULTS.md)。独立只读审查反馈已修复，运行证据以附件为准。

## 已知限制与未验证项

- 没有完整 rc.3 Electron 安装和界面验收，未安装到日常环境；没有真实模型长期质量、整日稳定性或生产迁移验证。
- 条件召回为确定性关键词匹配；项目状态来自记录，不是文件监控。需要模型主动检查原文、当前文件和测试。
- 后续用户要求按原顺序保留，必要内容超过预算会保留历史、停止新增压缩；不保证任意长任务都能压至目标容量。
- 混有其他插件或未知字段的动态上下文保守保留。已有 arc_ 检查点必须保留相容读取器、日志和清单。
- 没有 M-C 图形工作台、后台自动摘要、自动语义冲突判断或 M-C 同会话组合验收。旧 0.2.0-rc.2 的声明与降级保留，新能力以 rc.2/rc.3 证据为准。

## 未来可以改进

以下是建议，不是本版已实现能力：为项目状态增加可审阅编辑界面；建立真实长任务 A/B 评测；针对大历史做检索与来源认证性能优化；用 CI 自动核对双仓库共同核心和发布包，防止维护分叉。
