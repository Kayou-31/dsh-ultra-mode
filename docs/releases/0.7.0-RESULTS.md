## 修复与失败记录

新能力第一次全量测试为 743 项、703 通过、38 失败、2 跳过。原因包括测试的模块映射缺少新配置模块、旧断言仍期待静态恢复消息、正则把源码字符串中的 from 误判为 import，以及新增分页测试未模拟原生 tool/call 事件。修正为新的动态上下文断言、编译器依赖解析和完整原生事件序列后，最终单次全量为上表 745 项；没有用定向成绩拼接全量成绩。

独立只读审查发现并修复了：无关检索事件导致分页 revision 自失效、后续用户改向在“继续”时被条件过滤、模型整理文本冒充强制用户要求、历次自有动态快照反复进入归档胶囊。修复后的回归通过，审查未发现剩余发布阻断。审查本身不是运行测试。

独立仓库最初未锁定的 npm install 扩大解析依赖，停止后改用已验证依赖图生成独立锁文件；npm ci 在独立目录完成。临时构建脚本首次生成的模板转义错误已修复，不属于发布源码运行错误。

## 证据边界

- 原生 SDK 与实际包验证使用隔离数据和脚本化宿主；没有新增付费模型请求。
- 没有完整 rc.3 Electron 安装、菜单或界面验收，没有安装或修改日常 profile。
- 进度是记录状态，不会重新扫描代码或运行测试。verified 是记录中的状态，不是当前工作区重新通过验收。
- 关键词召回不是 embedding 检索，未验证真实模型的成功率、长任务收益、整日稳定性、真实断电或生产迁移。
- 后续真实用户要求保留原顺序，不由模型决定可以删除哪些要求；必要内容超过字节预算时保留原历史、暂停新增压缩。仍可能超出模型窗口，需要显式整理或另行续接。
- 只有精确匹配本插件单独 section 的 native snapshot 从胶囊正文中外置；混合或未知 runtime-context 仍完整保留，不保证所有任务都能压至目标预算。
- 新能力主要验证 rc.2/rc.3。旧 0.2.0-rc.2 保留已有声明与能力降级，没有重跑本次最终包矩阵；没有验证与最新版 M-C 同时管理同一会话。
- 0.6.0 的真实 OCG 14/30 和约 65K 属于历史案例，不能用作新版本结果。

## 复现

主仓库：npm ci --ignore-scripts → npm run build → npm run typecheck → 设置 DSH_ULTRA_TEST_SDK 为 node_modules 绝对路径 → npm test → npm run test:benchmarks。

独立仓库：npm ci --ignore-scripts → npm run build → npm run typecheck → 设置同一 SDK 环境变量 → npm test。构建无需父仓库，不需要任何 M-C 文件。lib 为发行入口和声明，work/test-lib 是测试编译目录，不随发行包发布。

实际包矩阵脚本在主仓库 scripts/verify-release-packages.mjs，参数 --sdk / --packages / --work；--work 必须是新的空目录。源码 ZIP、所有 TGZ 和证据附件哈希见 SHA256SUMS.txt。
