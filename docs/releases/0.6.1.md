# v0.6.1：DSH 0.2.1-rc.3 兼容更新（三包）

完整 Ultra **0.6.1**、独立 Memory **0.1.1**、独立 Decision **0.1.1**。本版把三包兼容范围扩展到官方 DSH `0.2.1-rc.3`，保留明确声明的 `0.2.1-rc.2` 和 `0.2.0-rc.2`，按 Memory-Continuity 的文档结构重写中文首页。

本版没有修改核心运行算法、默认开关、存储格式或授权范围。借鉴 M-C 的分层记忆、条件注入框架并加强主动进度查询是[后续设计方向](../proposals/memory-continuity-context.md)，没有包含在本次功能中；两个插件保持独立。

## 改动

- 三包 `engines.dsh`、原生 peer 同步为精确的三个版本集合；未声明未来 RC 或正式版兼容。
- 开发依赖与锁文件固定官方 rc.3，避免 npm 的 `latest` 标签仍指向 rc.2 时误测旧环境。
- 原生归档、持久化、组合、模型池与知识用例识别 rc.3；修正新版 SDK 不再接受 `mode: both` 的测试夹具。
- CI 配置 Ubuntu／Windows、Node 22.23.3、串行测试及显式 SDK 路径，增加三包版本边界回归。
- 中文 README 说明三包选择、默认行为、安装回滚、历史结果和当前限制。旧实验文件保留。

## 本机验证

Windows，Node **22.23.3**。全部 SDK 环境在独立开发目录，未安装到日常 DSH profile。

| 检查 | 结果与边界 |
| --- | --- |
| rc.3 类型检查与构建 | 通过；生成主包 Host/client、两个自包含附属包及来源清单 |
| rc.3 全套回归 | **730 项：728 通过、0 失败、2 跳过**；跳过项为 Windows 目录／文件符号链接权限。版本门控的原生用例已执行 |
| 兼容范围回归 | 3 包接受所声明的三个版本，拒绝未声明的 rc.1、rc.4、0.2.1 正式版和 0.3.0 |
| 业务案例自检 | **66 项参考检查通过**；缺陷基线按预期失败，真实模型请求 0；不是模型质量对照 |
| 最终 TGZ 接线 | 使用 `verify-release-packages.mjs` 对 rc.3 与独立 rc.2 SDK 分别核验；实际通过情况、包 SHA256、SDK 清单和七种安装顺序记录在 Release 的验证附件中 |

TGZ 脚本检查实际解包文件的来源 SHA、主入口、类型、默认 patch、原生 Loader 加载、唯一 evidence 工具、剩余 lease、配置权威和工具注册保留，以及最终清理；也检查权威切换已结束且服务错误列表为空。三个单包加 Memory＋Ultra、Ultra＋Memory、Memory＋Decision、Decision＋Memory，共七种顺序。agents 使用惰性夹具，没有实际执行检索或创建模型／子代理；不能当作 CLI 或 Electron 验收。

旧 `0.2.0-rc.2` 仅保留原有兼容声明与版本范围回归，本次没有重新安装该旧版做三包验收。rc.2 的独立包接线结果也不等于 rc.2 全量测试。

## 失败、修复与未验证项

- 首次 Node 24 测试在一个文件的断言输出后没有正常退出，已终止该测试进程；不计成功。切换既有 Node 22 工具链后取得上述完整退出结果，未据此推断具体运行时根因。
- 初次 rc.3 全测的两个失败来自旧测试夹具 `ToolRuntime mode: both`；改为原生 `native` 后，针对回归和完整套件均通过。失败日志与最终日志一起保留。
- 首次 Windows CI 有 1 项失败：runner 的 TEMP 使用 8.3 短路径，而原生验收门使用规范路径，测试夹具派生的绝对日志路径被判为目录外。夹具现先以 `realpathSync.native` 规范化临时根目录，保留原有目录边界检查；复验状态以对应提交的 Actions 结果为准。
- 没有新增真实模型实验、rc.3 Electron 安装／界面验收、长时间稳定性或模型质量对照。脚本响应和离线检查不证明这些能力。
- 0.6.0 的约 65K、14/30 等结果属于旧版特定实验，原始长测结论仍为 failed；没有转写为本版成功。
- 未验证与 Memory-Continuity 最新版同时管理同一会话的兼容性。
