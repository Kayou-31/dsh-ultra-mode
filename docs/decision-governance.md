# 可选决策治理：意图、诊断与验收

适用于本地检查点 **0.6.0-dev.2**，目标宿主为精确的 `0.2.0-rc.2 || 0.2.1-rc.2`。`decisionGovernance` 默认 false。开启后，现有 decision 在原调用中处理任务意图、运行中诊断和最终验收，便于按用户原文与实际来源核对结果。该配置不新增独立优化器、研究路线或模型调用，也不强制辅助模式再调用一次最终审查。

## 配置与使用

先在独立测试 profile 合并[示例](decision-governance.example.yml)中的 `decisionGovernance: true` 到既有 `ultra-mode` 条目。保留其他配置和 `collaborationModelPool`，不要插入重复 bundle，不需要配置新模型或凭据。建议同时保留 `evidenceEnabled: true`，使治理记录进入现有共享 EvidenceStore；持久化状态仍须按实际结果核对。

示例将 `concurrency` 设为 2，但不会替用户开启 Ultra。在会话中手动选择 `/ultra 2`，再提交实际任务。原有 Ultra 关闭、Agent＋只读辅助、手动 2～5 路以及独立 Team 开关保持原用法；普通模型池仍只影响其适用的普通子代理，不接管主模型、worker 或 decision。

并发模式沿用规划、协调及最终调用；辅助模式在其已有观察调用中处理治理材料，只有确实返回验收报告才记录验收结论。没有新增最后一次调用，不应把辅助已结束当作已经终验。

## 原文与意图

任务契约保存完整原始任务、宿主 `sourceId`、SHA256 和任务版本。提炼结果分成 `goals`、`constraints`、`acceptance`、`assumptions`，各项具有稳定 ID 和来源身份。

- `provenance: user` 必须附原任务中的连续 `quote` 和对应宿主来源；`text` 必须逐字等于 `quote`。引文相反的转述会被拒绝。
- 解释、方案与建议标为 `machine`，不能带用户引文来源，也不能增加用户授权或硬性验收条件。
- 完整原文始终进入下游任务入口，摘要无法覆盖它。宿主始终保留 `task-result` 作为原任务整体的验收项，再加入提炼的用户条件；模型不能把保留 ID 改成一个容易满足的局部要求。

宿主校验来源、字段和逐字关系，不声称理解了全部自然语言语义。原文中的否定和限制仍需执行者遵守；引用来源真实，也不代表模型的解释一定正确。意图协议失败会留下错误并沿用原有规划修复／降级边界，原始任务整体仍然保留。

## 诊断与投递

协调响应的建议包含任务版本、哈希、目标路线、类型、原因、证据 ID、具体指令、停止条件和 TTL；有需要时附 `replaces`。类型为 `redirect`、`verify` 或 `stop`，其中 `stop` 表示停止重复探索或按条件收口的建议，不是强制取消进程。宿主拒绝其他任务、非活动路线、未知来源、过长字段和越界 TTL。

每条路线最多一个待处理方向。相同建议跨轮去重，不通过重放续期；改变方向须有新证据。替代当前待处理方向时必须明确指出原 ID。到期、路线结束或取消会关闭尚未生效的待处理建议，账本达到上限时拒绝新条目，不静默清掉旧记录。

非空建议全部未通过协议校验时，本轮计入已有的协调失败限制；合法空建议和去重不算失败。辅助旁路停止后，已经准入但尚未发出的失效建议仍受请求守卫限制，直到父轮次结束或代理释放；若失效内容已经进入不可改写的历史，守卫拒绝该次请求并报告原因。已发出的请求无法撤回。

| 记录 | 能证明什么 |
| --- | --- |
| `queued` | 建议已接受并等待原生后续步骤，尚不证明已进入模型输入 |
| `admitted` | 宿主在原生 pre-step 边界实际准入 |
| `request-visible` | 宿主在实际请求中观察到该建议，并记录来源 |
| `effect-verified` | 独立宿主条件证明了效果；与“之后发生过工具调用”不同 |
| `cancelled / expired` | 待处理状态已关闭；若早已进入请求，仍保留可见事实，不宣称撤回 |

生产路径不会自动设置 `effect-verified`。独立效果证明必须由可信宿主观察完成。收到建议、接收消息、模型自称采用以及实际产生所需效果分别核对。

## 验收与审计

最终已有调用返回交付正文和 `verification.criteria`。每项引用契约中的 `criterionId`，状态为 `satisfied`、`failed` 或 `unverified`，并附依据或缺失证据。`satisfied` 与 `failed` 必须引用宿主已经观察到的实际工具结果来源；用户原话、模型总结及报告自身不能充当完成证据。

所有用户条件必须覆盖，包括 `task-result`。缺项、未知来源或错误协议均不放行，交付明确标记完成状态未验证；证据不足填 `unverified`。机器建议可以作为额外检查，但不计入新增硬性完成门槛。即使所有必需项都判为满足，报告仍是 `assessment: model`、`hostVerified: false`，不是宿主自动证明任务成功。

治理快照通过共享 EvidenceStore 的 `recordGovernance` 持久化，不另建会话事件体系。紧凑 RPC／UI 状态展示任务哈希、原文字数、意图条数、不同投递阶段、验收概况、持久化状态和错误。完整原生工具、会话及 JSONL 仍由 DSH 管理；持久化失败、缺证据或覆盖不足不能写成已验证。

## 架构与宿主兼容

`decision-contract` 是独立协议与账本，`decision-governance` 将它组合进现有 orchestrator／assist。模型调用、工具执行、权限、原生收件箱、pre-step、会话及 JSONL 都由 DSH 拥有。插件不复制上游优化器的运行时、shell hooks 或全局配置。

兼容范围只声明 `0.2.0-rc.2` 与 `0.2.1-rc.2`，不推断其他版本均适用。新版原生 continuable 子代理在每次创建和冷重建时重新应用相同继承工具限制，避免恢复后放宽工具范围。普通协作模型池的选择、预算、快照与审计继续保留；旧宿主回归和新宿主验证分别记录。

## 迁移与回滚

1. 保存当前 TGZ、哈希和 profile。先在独立 profile 安装当前候选，核对精确宿主版本；不要把本地检查点视为公开 Release。
2. 保持 `decisionGovernance: false` 检查旧模式和模型池，再合并示例显式开启。已有会话与在途任务不作为热迁移对象，新会话用于核对契约、原生投递和验收状态。
3. 关闭时设回 false，结束当前测试任务并重启／开启新会话，使后续任务使用原协议。需要回退整个插件时恢复旧包及其匹配 profile，保留本次审计材料；旧版无法识别新字段时一并移除 `decisionGovernance`。

配置开关不会撤回已进入模型请求的建议，也不会撤销已执行操作。旧发布包及安装说明见[安装与回滚](installation.md)；历史测试结果仍归原版本。

## 验证范围与参考

本轮采用离线协议、SDK／原生 CLI 接线与隔离 profile 验证，最终 TGZ 的哈希及逐项结果以交付材料为准。脚本化响应不证明真实模型智能或业务效果；实际 Electron 完整界面未运行。没有据此宣布在线模型、日常环境、推送或发布完成。
