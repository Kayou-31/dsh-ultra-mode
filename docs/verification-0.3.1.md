# 0.3.1 验证记录

目标宿主为 DSH Desktop / Host 0.2.0-rc.2。本轮真实模型证明五路独立执行、每路普通子代理，以及决策路线在执行期间反复跨路改向的机制可用；代码审查任务的 repo 内只读约束未完全遵守。机制通过与任务约束失败分别记录，不能将本轮描述为所有模型判断和行为全部通过。

## 版本与证据对应

真实模型运行在 0.3.0 安装包上，其 SHA-256 为 `a4a00b7a3ce923b4cc3a2b40489e6c129e56d8f1dc1cb6273eb47718f89c71d2`。本记录中的真实运行结果均属于该包，没有在 0.3.1 上重新请求真实模型。

0.3.1 仅在协调提示词中明确现有解析器限制：`assessment` 不超过 2000 字符，完整 JSON 响应不超过 16000 字符。解析器、改向通道及其他 runtime/client 行为未改。编译后的 20 个 lib 文件与实测包逐一比对，仅 `coordination.js` 和对应 source map 变化，其余 18 个字节一致。这个比对支持变更范围，不替代 0.3.1 的真实模型复验，也不保证模型一定遵守提示词长度。

0.3.1 构建和 host/client 严格 TypeScript 检查通过。普通 JIT 下运行 `node --test test/orchestrator.test.mjs test/ultra.test.mjs`，31/31 项通过，无失败、取消或跳过，退出码 0。另一次 `--jitless` 目标测试的 31 项断言通过，但 orchestrator 测试子进程未正常退出，在约 98 秒后停止已核实属于该次测试的进程，整个尝试退出码 1；不能记为该命令成功。0.3.0 原有 76/76 项 `--jitless` 成功结果保留在[历史验证记录](verification-0.3.0.md)，没有以它替代新版本的目标检查。

## 真实模型与运行中决策

本轮长任务只读核对了主会话、5 个 worker、1 个 decision 与 6 个普通子代理，共 13 个相关会话。worker 的 origin 为空、delegationDepth 为 0，彼此独立；每路真实调用普通 `subagent`，第 5 路调用两次。6 个 child 的 origin 均为 `subagent`、depth 均为 1，真实完成，未将 worker 本身计作子代理。全部 13 条内部请求配置记录为 Max；配置记录数量不等于模型请求总数。

5 路首个 turn 共同活动 114575 ms；首段已记录模型流共同重叠 901 ms。前者是会话活动区间，后者是日志流片段的观察区间，都不是精确网络请求时序、首输出等待或模型算力测量。

同一个 decision 完成 23 个串行 turn：1 次规划、21 次运行中协调、1 次最终交付。宿主接受 17 条方向指令。17 条均交叉核对到原生 next-step 消费、持久的 user/message 准入、同一 worker 原始 turn 内的后续真实模型步骤，以及发生在目标结束之前；没有把仅入队的指令写成准入成功。

仅对以下 3 个实际采纳案例另做了具体行为核对，不能把 17 次准入写成 17 次正确、有效或完全服从的决策：

| 协调轮次 | 目标路线 | 实际行为证据 |
| --- | --- | --- |
| 4 | 5 | 收到共享的 steer 准入/结束问题后，实际读取所指定的 runtime 源码与测试段落进行核查。 |
| 12 | 5 | 收到第 4 路的 client 发现后，在第 5 路仍运行时准入，并实际读取所指定的 client 源码段落。 |
| 17 | 5 | 收到停止 repo 外读取的纠偏后，明确登记越界；其后该 worker 未再调用读取工具。 |

这些案例证明方向反馈影响了后续实际行为，不证明模型提出的代码缺陷全部成立。该代码审查结论的正确性不属于此运行机制验收。

第 10、11 次协调的 `assessment` 分别为 2028、2036 字符，超过已有 2000 字符限制。两次响应虽是带规定字段的 JSON，仍被解析器拒收并保留为错误；第 11 次提出的 3 条指令没有计入接受数。后续协调继续运行。0.3.1 的提示词修订针对这两次拒收，不放宽解析器限制。

## 任务失败项与可观测性边界

worker 及其子代理没有发生写入、命令执行或联网工具调用，但存在 19 次明确的 repo 外只读尝试：6 次指向宿主安装目录，13 次指向项目中的 repo 外目录；部分路径查询失败，至少一条 worker 读取实际成功。另有 3 次工具返回内容的辅助溢出文件读取，单独统计，不混入上述 19 次。只读工具权限限制写入和执行，没有强制每个可读路径必须处于任务指定的 repo 内。这违反本轮代码审查范围，必须保留为任务约束失败。后续纠偏实际生效，不抹去先前越界，也不将这些材料作为公开的代码审查证据。

第 2、3 路的后台子代理分别在 worker 首次报告结束后约 39140、26898 ms 完成，随后原生回信触发额外的 2、1 个 worker turn。最终保留日志中的 6 个 child 均已完成，但 runUltra 的首次报告快照没有等待这两个较晚完成的 child，不能将后来的回信追记为首次报告已经包含的证据。这些额外 turn 来自原生后台回信，不是改向残留。

本机 SDK 的 request/context 日志记录元数据，没有保留真实请求消息正文。指令准入证据来自持久 user/message、next-step 消费和之后实际执行的模型步骤；请求消息包含方向指令的判断，还结合了单独核对的 SDK buildRequest → deriveMessages 管线。这是有结构支持的推断，没有声称观察到原始网络请求正文或思考内容。

此前 0.3.0 五路算术的 14/30/55/91/140 及五个真实普通子代理证据保留为独立历史案例。该算术运行的改向接受数为 0，不用它代替本轮长任务的实际改向证据。3/4/5 路全部组合的 SDK 集成仍是离线 fixture；本轮真实模型长任务只覆盖 5 路。

本记录没有新增 DSH 原生界面验收。实色按钮和菜单的独立浏览器检查见历史验证记录；Jev 真实账户调用、连续长任务、未来宿主版本以及 0.3.1 再次真实模型运行仍未验证。公开机器可读摘要见[脱敏实测摘要](real-model-0.3.0-summary.json)，不包含真实会话标识、个人路径、私人日志、原始提示词或思考内容。
