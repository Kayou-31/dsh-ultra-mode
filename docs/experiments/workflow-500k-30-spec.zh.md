# 500K 上限 / 420K 触发 / 30 次压缩 / 压后含预留 130K 验收口径

用户本轮确认的口径取代先前“每次压缩前约 500K 实际输入”：单 Agent 上下文总上限为 500,000 token，在约 420,000 token 触发压缩，至少完成 30 次独立压缩后仍保持任务一致性。使用官方 DSH 0.2.1-rc.2、OCG deepseek-v4.1-flash 和独立 profile。日常配置不参与写入。

后续追加的归档验收还要求：每个合格周期压后**实际输入加输出及工具预留不超过 130,000 token**。原基线的 30 周期一致性通过与此新增效率目标分开判断，不能追改旧结果或用早期少量小请求冒充整个 30 周期达标。

## 工作负载

用可复现的隔离工程模拟至少一整天项目进程，包括初始约束、逐步实施、真实工具执行和测试结果、中途新增要求、替代决策、未解决冲突及收尾验收。模型需要实际修改项目并执行测试。大型上下文来自不同测试用例的详尽执行报告，不以重复填充或连续摘要替代工程过程。

模拟的项目时间线、实际墙钟运行时间、模型等待时间分别记录。覆盖一天的模拟时间不等于真实运行满 24 小时；若未做墙钟 24 小时耐久测试，必须标作未验证。

## 计数与预算

- 一次合格压缩周期必须有可关联的压缩前实际请求、独立的原生历史替换事务、压缩后实际请求和可校验的原文恢复。
- 同一事务内替换多条消息只算一个周期；任务轮次、模型请求数、被替换消息数分别统计。
- 500K 总窗口应包含宿主指令、工具定义、消息、检索返回与输出预留。420K 触发量和压后目标分别列出，不将现有 soft target 冒充硬窗口限制。
- 宿主估算值与 provider 实测回执分开。实际输入含缓存命中输入；不得只统计未缓存输入，也不得把估算值写成实测。
- native-meter floor 采用官方 token meter 的 usage 锚与 surface 变化估算；本地 decoded-message 估算计入原始正文、工具参数、reasoning、framing、工具定义及 rich／unknown 结构回退，避免重复计算 JSON 传输转义或宿主消息 metadata。两者取较大值并始终标为 estimated，均不是 exact tokenizer；准入未超估算上限不保证 provider 实际值必然未超窗，也不证明压缩无损。
- 先跑小规模校准和单周期闭环；超窗、缺少实测回执或不满足触发口径的周期不计入 30 次验收通过数。

## 逐轮 130K 与首请求门槛

归档组为每个合格事务分别核验两列：首个实际压后请求，以及原验收选择的首个缓存分桶一致压后请求。最终各须有 30 个唯一周期／事务，实际输入都按 provider `totalTokens-outputTokens` 计算，再加至少 8,192 输出与 2,048 后续工具预留；两列都不能超过 130,000。

首条准入请求必须就是该事务声明的 `nextRequestSequence`，有完整原生结算与 gate 对应、正的实际输入和合法预留。首条请求失败且 usage 不明、待结算或实际超限，均不能通过完整实验验收；不允许跳过它，另选后续较小请求。选择的分桶一致请求也必须是首个可核验的一致请求，不能跳过较早已知一致或超限样本。所有辅助／准备归档事务另表列出，不用于凑足 30 个合格周期。

有 actual total/output 却缺少 `cacheReadTokens` 桶时，仍可独立核验首请求实际总输入，但缓存桶保留缺失，`consistent` 为 null；不补成 0，也不把“桶缺失”当作“调用失败”。同时保存首个完整一致分桶请求，保持旧验收口径可对照。图的归档恢复主曲线优先显示首个实际请求，CSV 并列保留所选一致请求，不能把两种样本混成同一列。

最终必须由 outcome、原生终态 judge、独立来源审计及两种 130K 附表共同关闭。运行中有部分合格周期或有离线 30 次 append/replay，均不够宣称真实模型 30 次压缩通过；未知首请求或高于 130K 时不能提交为已完整实测的正式版。

## 一致性判断

首轮只出现一次的硬约束始终有效；新增要求正确纳入；被替代的决定保留来源和版本；计划、已执行、已验证正确区分；已完成操作不重复执行；摘要遗漏事实可从原文取回并验证 SHA；冲突保持未解决直至有明确证据。最终以模型公开答案、真实项目文件、测试、操作 receipt 和原生会话共同核验，不能只凭模型自评。

可在稳定检查点冷恢复，恢复后不重放既有操作。对已完成提交但 final 连接失败的阶段，仅在显式 resume 下只读补齐 final 核验，不重复旧工具变更或提交；后续新阶段仍按原授权继续。官方有界 TRANSPORT 重试只在本次显式验收 profile 开启，最多 2 次，默认重试仍为 0，不改变产品默认。错误流包装中的 0 usage 属于 unknown，不作真实零消耗或成功调用计费；费用依唯一 gate ID 和最后 provider usage 去重，旧失败与新增调用分开。失败保存原始结果与阶段状态，修复后尝试另行登记，不改写失败为通过。不导出私有思维链、密钥、原始私有 profile 或未经筛选的会话日志。

本次 C-b 的恢复适用于已完成测试、原始 get-before-commit、SHA 和磁盘 commit，只是最终输出因 JSON 围栏后附带额外说明而被严格 parser 拒绝的情形。原答案仍失败，不能通过裁切尾文来改判。新只读 final 回合须独立验证正确格式、相同来源／决定／操作结果及业务文件不变；第一个恢复回合禁用 patch、test、commit，防止重执行。原失败文件、原生日志前缀和请求账本先封存，后续新增请求额度与时间从同一个有限预算中扣旧。
