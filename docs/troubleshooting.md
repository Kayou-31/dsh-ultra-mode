# 排障与反馈

先确认插件版本、DSH Desktop／Host 版本和实际加载状态，再定位症状。加载成功、界面可点击、SDK 检查通过、真实模型完成和业务结果正确分别是不同层面的证据。安装过程见 [安装指南](installation.md)，执行与权限边界见 [架构说明](architecture.md)。

## 按钮没有出现

确认已选择会话，并且 `@dsh-external/dsh-ultra-mode` 在当前 desktop profile 的 bundles 中启用。当前兼容目标是 DSH Desktop / Host 0.2.0-rc.2；旧 0.1.x 或更新版本不能直接按本版兼容结论处理。

升级后完整退出并重新打开 DSH，包括托盘／后台实例。检查插件加载错误和客户端注入错误；不要因为界面刷新成功便假设 Host 已经更新。若是整体白屏、某个 slot 异常或浮层挡住输入框，分别记录现象，不把它们都归因为 Ultra。

## Ultra 菜单显示 HTTP 405

先保留错误文本，完整重启 DSH 与 Host，再重新选择会话打开菜单。历史案例中 Host 未重新加载时出现过此错误，完整重启后消失；这不代表每个 405 都有同一原因。

重启后仍出现时，提交插件与宿主版本、发生时间、菜单错误和是否重新加载 Host 的证据。不要通过关闭宿主保护或随意修改全局路由来绕过错误。

## 选项变化，当前任务却没改模式

按钮选项按会话隔离，运行中修改只影响后续任务。`/ultra off` 保留当前选择，`/ultra on` 恢复它；新会话首次开启并发默认 3。状态驻留 Host 内存，重启后复位。

`/ultra 1` 是普通主 Agent + 决策辅助，不是一个 Max worker 接管任务。主 Agent 的模型和思考设置在辅助模式中保持不变，额外 decision 固定 Max。

## 没有看到即时改向或全过程

当前内部路线不在主会话逐路展示，主会话主要呈现最终交付。辅助模式保留普通主 Agent 的过程，旁路决策仍不逐步展示。不要把可见主 Agent 的思考当成内部 decision 的原始思维链。

方向只在新进展触发后通过下一模型步骤处理，已经发送的请求无法中途改变。短任务可能先结束；指令入队、在原 turn 持久准入、助手实际采纳需要分别核对。三次协调返回空方向也可以是正常结果。

## worker 的命令或写入被拒绝

默认 worker 与运行中 decision 使用研究权限，写入、命令和发布由 decision 最终阶段统一处理。研究阶段的普通子代理也继承相应边界。这是运行策略；不要为了让研究路线执行写操作随意扩大 `researchTools`。

如果任务要求实际命令验证，应由最终 decision 或辅助模式的普通主 Agent 在原权限下完成，再报告实际结果。正确算术或模型自述不能替代指定工具、真实子代理或实际运行证据。

## 结果正确，但缺少普通子代理 ID

等待式普通 `subagent` 的返回值不一定带子代理 ID。插件观察宿主的原生身份并向 decision 提供，审计也可核对目录与 child header；这些来源要与工具直接返回区分。

`list_agents` 仅列可继续的子代理，one-shot child 可能不在列表中。没有列出不等于没有真实调用；也不能凭一段自述或一个 ID 证明其完成。不要为了补 ID 额外委派，或填入猜测值。

后台 child 可能晚于父路线首份报告结束，首份报告不会自动回填晚到结果。遇到此情形应明确最终报告的时间边界。

## 审批、超时与取消

最终写入仍使用原 DSH 权限。工作目录与继承策略范围不同会触发正常审批；已出现的 allowed-once 不代表所有后续工具都授权。按宿主提示决定，保留同目标重试和实际结果。

取消、超时、失败或卸载可能导致没有最终交付。并发任务至少需要两份非空完成报告才进入最终 decision，但报告存在不等于业务成功。辅助建议失败不会替主 Agent 改写任务状态，也不会为补建议额外唤醒它。

辅助停止时只清理本运行仍待消费的反馈，保留人类消息、其他运行消息与已准入历史。达到有限预算只停止新 decision run，现有建议仍可在原 turn 消费；这个预算不是 provider 请求数上限。

## 非法 JSON 或格式修复失败

严格协议错误会保留。插件不从叙述、多对象或非法正文中猜选一个“看似正确”的指令。

规划最多在同一 decision 上下文修复一次；再次非法或修复 provider 失败时按稳定路线索引降级，保留用户每路动作并公开错误。首次 provider 请求失败仍结束任务。辅助只有在原主 turn 活跃、预算足够时做单轮有界修复；失败反馈不入队，不无限重试。

要求每路真实派 child 时，父路线自行算出的值不能替代没有创建或完成的 child。报告 completed 也不能抹掉这种业务失败。

## Jev 不可用

Jev 默认关闭，辅助模式不调用它。并发模式启用后，Host 环境必须有配置的密钥变量；缺密钥、超时、HTTP 错误或无效响应会明确回退到内置 Max decision。不要把密钥填进聊天、Issue 或客户端 RPC。

目前 Jev 只有离线协议 fixture 证据，没有真实账户验收。数据发送范围见 [可选 Jev](architecture.md#可选-jev)。

## 测试跳过或 Windows SDK 退出失败

发布 CI 的 97 项通过之外，5 项实际 SDK 检查因环境缺少 SDK 而跳过；这是未执行，不能算通过。指定实际 SDK 时，应使用该宿主安装的匹配库。

Windows 早期实际 SDK 的普通 JIT 与 `--jitless` 尝试曾在断言通过后退出失败，普通 JIT 包含 V8 `node->IsInUse` 致命错误。保留这个失败，不据断言数写成整个命令通过，也不把添加 `--jitless` 当作通用解决方案。后续定向实际 SDK smoke 与这次历史失败分开记录，详见 [验证记录](verification-0.3.2.md) 与 [测试指南](testing.md)。

## 提交可复现反馈

使用 [Bug 模板](https://github.com/Kayou-31/dsh-ultra-mode/issues/new?template=bug_report.yml) 提供版本、所选模式、最短复现、预期和实际结果，以及相应层面的证据。注明来源是 mock、实际 SDK 脚本、真实模型还是 UI。

只附最小脱敏片段：删除 API 密钥、账户信息、个人绝对路径、原始会话 ID、任务敏感内容与原始思维链。不要上传完整 profile、完整会话 journal 或完整请求正文。敏感漏洞按 [安全约定](../SECURITY.md) 联系维护者。
