# 上下文压缩对 M-C 经验与结构的复用

状态：**本设计的首个工程实现已纳入 Ultra 0.7.0 / Memory 0.2.0；真实模型收益未验证**。已实现五层预算注入、关键词条件召回、`ultra_memory_status` 三级展开与版本分页。以下保留设计思路，文件事件触发、智能冲突判断等未实现建议不能当作已交付能力；实际 API 以 [Memory README](../../packages/dsh-ultra-memory/README.md) 为准。复用 M-C 经验，不合并插件、运行时或数据。

## 想解决什么

长任务需要同时保住三类信息：当前必须遵守的约束、任务已经推进到哪里，以及随时能够核对的原始证据。把整个历史留在模型窗口里成本高；只给一份摘要又可能丢失因果、过期或混淆计划与完成。

方向是在压缩插件内部，按 M-C 的结构经验组织“现在需要知道什么”，通过现有证据层保存“当时实际发生了什么”，让模型按需主动查看进度和证据。目的是提高任务接续和证据使用的可靠性，不声称改变模型本身的推理能力。

## 一份状态，三种读取方式

| 方式 | 触发点 | 内容 |
| --- | --- | --- |
| 分层基础注入 | 每次请求按预算生成 | 目标与硬约束、当前任务／阻塞、关键结论和来源索引；只带当前必要内容 |
| 条件检索注入 | 当前问题、文件、任务阶段或冲突命中条件 | 与当前操作相关的历史记忆；有命中理由、预算和去重，未命中不强行加入 |
| 模型主动查看 | 开始实施、恢复会话、遇到矛盾或准备提交结果时 | 请求当前项目状态，再按需展开某个阶段、决策依据或原文；支持查看上次读取之后的变化 |

这三种读取方式在压缩插件内部共用状态与来源索引，避免维护互相矛盾的自动摘要和工具报告；不读取 M-C 的人物数据。具体工具名、数据结构和触发规则应在后续接口设计时确定，不能把此表当作已存在的公开 API。

## 分层建议

复用 M-C 在层次预算、优先级和确定性排序上的结构设计；工程内容不必硬套人物关系字段：

1. **目标与硬约束**：当前用户要求、验收标准、明确限制。必要信息装不下时明确报告，不能静默删掉。
2. **当前任务**：活动阶段、分支／工作目录、下一步、阻塞和待决事项。
3. **已验证结论**：完成项、关键决策、对应源码版本、测试或产物证据。
4. **相关历史**：按条件命中才加入的尝试、失败原因和被替代方案。
5. **未完成事项**：尚未执行的计划、等待项与到期条件，不能因为被多次提及而升级为完成。

读取深度沿用“概览 → 关联 → 证据”的方向。首次只返回足以定位的短摘要，模型再决定是否读取正文。预算还要计入工具定义、读取结果、输出和近期上下文，不能只计算压缩后可见文字。

## 压缩与恢复的闭环

压缩前，把候选历史写入可恢复的原始证据并核对完整性；再提交状态摘要和来源索引；最后通过宿主唯一的历史管理者执行替换。任一步失败都不把未确认可恢复的内容当作已归档。

借鉴 M-C 的可追溯 packet，让压缩插件的检索结果指向对应来源 ID、修订号与内容哈希。原文仍保留，读取时核对当前项目范围和权限。被检索出的内容按数据处理，不能充当新的用户指令或操作授权。调用后形成短暂读取记录，避免同一请求重复注入同一段内容；读取结果不递归变成新的永久事实。

## 主动进度查询需要带什么

- 项目范围、任务 ID、更新时间和状态修订号；可见的采集覆盖缺口。
- 每项工作的 `计划／已执行／已验证／待复验／阻塞` 状态及证据引用。
- 验证时对应的源码或产物版本。文件更新或验证依赖变化后，旧通过记录保留为历史，当前状态提示待复验。
- 与上次读取相比新增、撤回、过期和替代的内容；不把“没有新记录”解释为“没有发生变化”。

记忆是查证入口。模型拿到“测试已通过”的记录后，仍需检查它是否适用于当前版本。无法自动追踪的外部修改应显示未知或覆盖缺口，不能承诺全自动准确进度。

## 推荐实现顺序与验收

先把 M-C 已验证的设计经验映射到压缩插件自己的数据和生命周期：复用层次预算、条件匹配、选择理由、来源追溯和失效判断的结构，沿用 Ultra 的工程证据存储与恢复协议。先跑通项目状态读取、来源跳转、修订失效、权限和预算，再考虑界面与自动触发。同一会话只允许一个压缩管理者；两个产品保持独立。

用冻结任务对比“当前 Ultra”与“借鉴 M-C 结构后的压缩插件”，记录恢复会话后的正确接续率、重复操作、过期结论采纳、错误召回、总输入量、检索次数与耗时。测试应包含撤回约束、源码更新、未完成任务、引用缺失、跨项目隔离、权限撤回和压缩中断。模型主动查询是否发生、查到后是否实际使用，也应分开记录。

只有结果支持时才宣称更省上下文或更可靠；压缩比例本身不能证明任务完成质量。
